1. Setting Up a Spring Boot GraphQL Server

Add the necessary dependencies to your build.gradle to use Spring Boot with GraphQL.

plugins {
    id 'org.springframework.boot' version '3.3.5'
    id 'io.spring.dependency-management' version '1.1.6'
    id 'java'
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-graphql:3.3.5'
    implementation 'org.springframework.boot:spring-boot-starter-web:3.3.5'
    implementation 'org.springframework.boot:spring-boot-starter-actuator:3.3.5'
    implementation 'org.springframework.boot:spring-boot-starter-websocket:3.3.5'
    implementation 'io.springfox:springfox-boot-starter:3.0.0'
}

Create a GraphQL schema in src/main/resources/graphql/schema.graphql (note the .graphql extension used by the official starter).

type Query {
    greeting: String
}

type Mutation {
    addMessage(content: String!): Message
}

type Subscription {
    messageAdded: Message
}

type Message {
    id: ID!
    content: String!
}

2. Implementing GraphQL Resolvers

Create resolvers for queries, mutations, and subscriptions in Java, using annotations from the official Spring GraphQL starter.

import org.springframework.graphql.data.method.annotation.Argument;
import org.springframework.graphql.data.method.annotation.MutationMapping;
import org.springframework.graphql.data.method.annotation.QueryMapping;
import org.springframework.graphql.data.method.annotation.SubscriptionMapping;
import org.springframework.stereotype.Controller;
import reactor.core.publisher.Flux;
import reactor.core.publisher.FluxSink;
import java.util.ArrayList;
import java.util.List;

@Controller
public class GraphQLResolver {
    private final List messages = new ArrayList<>();
    private final List> subscribers = new ArrayList<>();

    @QueryMapping
    public String greeting() {
        return "Hello, GraphQL!";
    }

    @MutationMapping
    public Message addMessage(@Argument String content) {
        Message message = new Message(String.valueOf(messages.size() + 1), content);
        messages.add(message);
        subscribers.forEach(sink -> sink.next(message));
        return message;
    }

    @SubscriptionMapping
    public Flux messageAdded() {
        return Flux.create(emitter -> {
            subscribers.add(emitter);
            emitter.onDispose(() -> subscribers.remove(emitter));
        });
    }
}

class Message {
    private String id;
    private String content;

    public Message(String id, String content) {
        this.id = id;
        this.content = content;
    }

    public String getId() { return id; }
    public String getContent() { return content; }
}

3. Configuring WebSocket for Subscriptions

Ensure WebSocket support for subscriptions by adding configuration. The official starter uses Spring's WebSocket support.

import org.springframework.context.annotation.Configuration;
import org.springframework.web.socket.config.annotation.EnableWebSocket;
import org.springframework.web.socket.config.annotation.WebSocketConfigurer;
import org.springframework.web.socket.config.annotation.WebSocketHandlerRegistry;
import org.springframework.graphql.server.webflux.GraphQLWebSocketHandler;

@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {
    private final GraphQLWebSocketHandler graphQLWebSocketHandler;

    public WebSocketConfig(GraphQLWebSocketHandler graphQLWebSocketHandler) {
        this.graphQLWebSocketHandler = graphQLWebSocketHandler;
    }

    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(graphQLWebSocketHandler, "/subscriptions").setAllowedOrigins("*");
    }
}

4. Client Example (JavaScript with Apollo Client)

Use Apollo Client to interact with the GraphQL server, including subscriptions over WebSocket.

import { ApolloClient, InMemoryCache, gql } from '@apollo/client';
import { WebSocketLink } from '@apollo/client/link/ws';
import { SubscriptionClient } from 'subscriptions-transport-ws';

const wsLink = new WebSocketLink(
    new SubscriptionClient('ws://localhost:8080/subscriptions', {
        reconnect: true,
    })
);

const client = new ApolloClient({
    link: wsLink,
    cache: new InMemoryCache(),
});

// Query
client.query({
    query: gql`
        query {
            greeting
        }
    `,
}).then(result => console.log(result.data.greeting));

// Mutation
client.mutate({
    mutation: gql`
        mutation($content: String!) {
            addMessage(content: $content) {
                id
                content
            }
        }
    `,
    variables: { content: "Hello, World!" },
}).then(result => console.log(result.data.addMessage));

// Subscription
client.subscribe({
    query: gql`
        subscription {
            messageAdded {
                id
                content
            }
        }
    `,
}).subscribe({
    next(data) {
        console.log('New message:', data.data.messageAdded);
    },
});

5. Debugging with GraphiQL

The spring-boot-starter-graphql dependency enables a GraphiQL interface when configured. Enable it in application.properties and access it at http://localhost:8080/graphiql.

spring.graphql.graphiql.enabled=true
spring.graphql.graphiql.path=/graphiql

Example query in GraphiQL:

query {
    greeting
}

Example mutation:

mutation {
    addMessage(content: "Test message") {
        id
        content
    }
}

Example subscription:

subscription {
    messageAdded {
        id
        content
    }
}

To debug, open GraphiQL in your browser, enter the above queries, and observe the responses. For subscriptions, keep the GraphiQL tab open and trigger a mutation in another tab or client to see real-time updates.

6. Monitoring with Spring Boot Actuator

The spring-boot-starter-actuator dependency provides endpoints for monitoring and debugging. Configure Actuator in application.properties to expose useful endpoints.

spring.graphql.graphiql.enabled=true
spring.graphql.graphiql.path=/graphiql
management.endpoints.web.exposure.include=health,info,metrics
management.endpoint.health.show-details=always

Access Actuator endpoints like:

  • http://localhost:8080/actuator/health - Check application health.
  • http://localhost:8080/actuator/metrics - View metrics like JVM memory usage.

Use these endpoints to monitor application performance and diagnose issues during development.

7. Implementing a REST API

For comparison, implement a REST API alongside the GraphQL server using Spring Boot's REST controller.

import org.springframework.web.bind.annotation.*;
import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/api/messages")
public class MessageController {
    private final List messages = new ArrayList<>();

    @GetMapping
    public List getMessages() {
        return messages;
    }

    @PostMapping
    public Message addMessage(@RequestBody MessageInput input) {
        Message message = new Message(String.valueOf(messages.size() + 1), input.getContent());
        messages.add(message);
        return message;
    }
}

class MessageInput {
    private String content;

    public String getContent() { return content; }
    public void setContent(String content) { this.content = content; }
}

This REST API provides endpoints to retrieve all messages (GET /api/messages) and add a new message (POST /api/messages). Test it using tools like Postman or curl.

8. GraphQL vs REST API Comparison

Below is a comparison of GraphQL and REST API approaches based on the above implementations.

Feature GraphQL REST
Data Fetching Single endpoint, client specifies exact data needs Multiple endpoints, fixed data structures
Over/Under Fetching Avoids over/under fetching with flexible queries Prone to over/under fetching
Real-Time Updates Native support via subscriptions (WebSocket) Requires polling or WebSocket setup
Versioning Typically no versioning, schema evolves Often requires versioning (e.g., /v1/)
Documentation Self-documenting schema, tools like GraphiQL Requires external docs (e.g., Swagger)

GraphQL is ideal for complex data structures and real-time applications, while REST is simpler for straightforward CRUD operations.

9. Using Swagger for GraphQL Schemas

While GraphQL has tools like GraphiQL, you can integrate Swagger (via Springfox) to document REST endpoints or expose GraphQL schemas as REST-like APIs. The springfox-boot-starter dependency is included for Swagger support.

Configure Swagger in a configuration class:

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import springfox.documentation.builders.PathSelectors;
import springfox.documentation.builders.RequestHandlerSelectors;
import springfox.documentation.spi.DocumentationType;
import springfox.documentation.spring.web.plugins.Docket;

@Configuration
public class SwaggerConfig {
    @Bean
    public Docket api() {
        return new Docket(DocumentationType.SWAGGER_2)
                .select()
                .apis(RequestHandlerSelectors.basePackage("com.example.demo"))
                .paths(PathSelectors.any())
                .build();
    }
}

Access the Swagger UI at http://localhost:8080/swagger-ui.html. For GraphQL, tools like graphql-voyager or graphiql are preferred, but Swagger can document REST endpoints or GraphQL queries exposed as REST (e.g., via a custom controller). To expose GraphQL schema in Swagger, use a library like graphql-java-servlet with a REST wrapper, though this is less common.

10. Other Methods: Streams and WebSockets

Beyond standard HTTP requests, Spring Boot supports additional methods for real-time communication:

  • Streams: Reactive streams (e.g., using Project Reactor's Flux or Mono) enable asynchronous, non-blocking data processing. In the GraphQL example, subscriptions use Flux to push messages to clients reactively. Streams are ideal for handling large datasets or continuous data flows, like real-time analytics.
  • WebSockets: WebSockets provide a full-duplex communication channel over a single TCP connection, used for GraphQL subscriptions in this guide. They enable low-latency, bidirectional communication, perfect for real-time applications like chat or live notifications. The WebSocket configuration above uses Spring's WebSocket support for GraphQL subscriptions.

Streams are best for server-side data processing, while WebSockets excel in client-server real-time communication.

11. Running the Application

Run your Spring Boot application using ./gradlew bootRun. Access the GraphQL endpoint at http://localhost:8080/graphql, GraphiQL at http://localhost:8080/graphiql, subscriptions at ws://localhost:8080/subscriptions, Actuator endpoints at http://localhost:8080/actuator/*, and Swagger UI at http://localhost:8080/swagger-ui.html.
